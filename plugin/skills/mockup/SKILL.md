# EDK 화면 시안 만들기

요청: $ARGUMENTS

지금 운영 중인 V3 고객사 화면과 **최대한 비슷한 모양**의 시안을 HTML 파일 하나로 만든다.
모양의 기준은 위키 서버가 프론트 코드에서 바로 뽑아 주는 테마 자료다. 색이나 크기를 새로 지어내지 않는다.

## 0. 로그인·서버 확인 — 안 되면 여기서 멈춘다
테마는 회사 코드에서 나온 자료라 **회사 계정으로 로그인한 사람에게만 서버가 내려 준다.** 플러그인 안에는 들어 있지 않다.
1. `node "${CLAUDE_PLUGIN_ROOT}/scripts/edk-auth.mjs" check` 를 실행한다. 실패(종료 코드 0 이 아님)하면
   "회사(Teams) 계정 로그인이 필요합니다 → `/edk-brain:login`" 이라고만 알리고 **멈춘다.**
2. `edk-wiki` 서버의 `theme_get` 도구가 없거나 401·인증 오류·연결 오류를 내면 그 사실을 알리고 **멈춘다**
   (로그인 직후라면 `/mcp` 에서 edk-wiki 를 다시 연결하거나 새 세션을 열라고 안내한다. 연결 오류면 서버 주소·서버 상태 문제일 수 있다고 전한다).
- 멈췄을 때는 시안을 만들지 않는다. 기억이나 추측으로 EDK 의 색·글자·화면 틀을 흉내 내지 않는다.

## 1. 테마 자료 받기 (매번)
`theme_get` 도구에 `file` 을 넘겨 받는다.

| file | 내용 | 받는 때 |
| --- | --- | --- |
| `patterns.md` | 규칙, 색·글자 고르는 법, 화면 틀, 자주 쓰는 조각, 본보기 화면 | **항상 먼저** |
| `template.html` | 화면 틀과 테마가 들어 있는 시안 뼈대 | 시안을 만들 때 그대로 받아 쓴다 |
| `ui-variants.md` | 버튼·입력·배지·탭·모달 등의 variant 클래스 원문 | `patterns.md` 에 없는 variant 가 필요할 때 |
| `edk-theme.css` | 색 변수와 글자 스타일 전체 | 토큰 이름을 확인할 때 |
| `SOURCE.md` | 어느 커밋에서 뽑았는지 | 근거를 적을 때 |

## 2. 무엇을 그릴지 정하기
- 요청이 모호하면(어느 메뉴의 화면인지, 목록인지 폼인지, 어떤 항목이 들어가는지) **먼저 물어본다.** 한 번에 두세 가지만 묻는다.
- 업무 규칙이 걸린 화면이면 위키로 확인한다(`wiki_search` → `wiki_read`). 예: 어떤 등급이 볼 수 있는지, 어떤 상태값이 있는지.
  위키에서 확인한 내용은 시안 설명에 근거(`wiki/<도메인>/<페이지>.md`)와 함께 적고, 확인하지 못한 것은 "가정"이라고 적는다.
- 기존 화면을 닮게 해 달라는 요청이면 서버 코드 도구로 그 화면을 찾아본다(`code_search`/`code_files` → `code_read`).
  **모양은 `patterns.md` 6절의 본보기만 따른다.** 본보기가 아닌 영역의 코드는 "무슨 항목이 어떤 순서로 있는지"만 참고한다.
- 코드 도구가 없으면(권한 역할이 없는 경우) 테마 자료와 위키, 사용자가 말해 준 내용으로 만든다.

## 3. 시안 만들기
1. `theme_get` 으로 받은 `template.html` 전체를, 사용자의 작업 폴더에 `시안/<YYYYMMDD>-<영문-소문자-주제>.html` 로 새 파일로 쓴다(폴더가 없으면 만든다).
   `<head>` 의 글꼴 링크·Tailwind 스크립트·설정·`<style type="text/tailwindcss">` 블록은 **한 글자도 바꾸지 않는다.**
2. `<!-- ▼▼▼ 시안 본문 시작 … -->` 과 `<!-- ▲▲▲ 시안 본문 끝 ▲▲▲ -->` 사이만 요청한 화면으로 바꾼다.
   - 목록형이면 `<main>` 바탕을 그대로(`bg-background-secondary`), 상세·폼형이면 `bg-background-primary` 로 바꾼다.
   - 왼쪽 메뉴에서 시안 주제에 맞는 메뉴를 활성으로 바꾼다(활성 항목의 모양은 뼈대의 주석 참고).
   - `<title>` 과 페이지 제목을 화면 이름으로 바꾼다.
3. 클래스는 `patterns.md` 의 규칙대로 쓴다.
   - 색·글자·반경은 토큰 클래스만. HEX, `text-[13px]` 같은 임의 값, Tailwind 기본 팔레트를 쓰지 않는다(`patterns.md` 에 "예외 값"이라고 적힌 것만 그대로 쓴다).
   - 배치용 클래스(`flex`, `grid`, `gap-4`, `px-8`, `w-[160px]` 등)는 자유롭게 쓴다.
   - 버튼·입력 등은 실제 컴포넌트의 클래스 문자열을 그대로 붙여 쓴다. 비슷하게 새로 만들지 않는다.
4. 동작은 3-1 대로 넣는다(그림만 있는 시안은 만들지 않는다).
5. 예시 데이터는 **지어낸 것**만 쓴다. 회사 이름은 `QA자동-…`, 사람 이름은 `QA자동-관리자` 같은 가명으로 한다.
   실제 고객사 이름, 사람 이름, 연락처, 이메일을 넣지 않는다(위키·코드에 적혀 있어도).
6. 화면 오른쪽 아래의 "시안 · 실제 화면 아님" 표시는 지우지 않는다.

## 3-1. 눌러 보면 동작하게 만들기 (반드시)
시안은 그림이 아니라 **눌러 보며 흐름을 확인하는 프로토타입**이다. 기획자가 "이걸 누르면 어떻게 되나"를 시안 안에서 바로 볼 수 있어야 한다.

1. **눌리는 것은 모두 무언가를 한다.** 버튼·링크·표의 행·탭·셀렉트·`>` 이동 버튼·숫자 칸까지, 눌러도 아무 일이 없는 요소를 남기지 않는다.
   - 시안 범위 안: 실제로 동작한다(아래 2~6).
   - 시안 범위 밖(다른 메뉴로 가는 왼쪽 메뉴, 상단 알림 등): 토스트로 "시안 범위 밖 · ○○ 화면으로 이동"처럼 **어디로 가는지** 알린다.
2. **가짜 데이터 저장소**: 예시 데이터를 스크립트 맨 위 `const db = {...}` 한 곳에 모으고, 화면은 늘 `db` 에서 다시 그린다(`render()`).
   만들기·고치기·지우기·상태 바꾸기는 `db` 를 바꾼 뒤 다시 그린다. 그래서 [만들기]로 만든 항목이 목록·건수·대시보드 카드 등 **그 데이터를 쓰는 모든 곳에 바로** 나타나야 한다.
   - `db` 는 `sessionStorage` 에 저장해 새로 고침해도 남게 하고(탭을 닫으면 사라지게 - `localStorage` 는 쓰지 않는다), 시안 도구 띠에 [데이터 초기화]를 둔다.
   - `sessionStorage` 를 못 쓰는 환경도 있으니 읽기·쓰기를 `try/catch` 로 감싸고, 실패하면 메모리에만 둔다.
3. **화면 이동**: 누르면 다른 화면으로 가는 곳(목록 → 상세, [만들기] → 만들기 화면)은 **같은 파일 안에 그 화면을 만든다.**
   주소 뒤 `#/…` 로 화면을 바꾸는 작은 라우터를 쓴다(예: `#/dashboard`, `#/reports`, `#/reports/3`). 브라우저 뒤로 가기가 동작해야 한다.
   - 미리보기 창처럼 주소를 바꿀 수 없는 곳에서도 동작하게, 현재 화면은 `route` 변수로 들고 `go(hash)` 가 `route` 를 바꾼 뒤 다시 그린다.
     주소 바꾸기(`history.pushState`)는 `try/catch` 로 되면 하고, `popstate`·`hashchange` 때 주소에서 `route` 를 다시 읽는다. `#/…` 링크는 클릭을 가로채 `go()` 로 보낸다.
   - 이어지는 화면은 요청한 화면보다 간단해도 되지만 브레드크럼·제목·그 화면의 핵심 항목·돌아가는 길은 있어야 한다. 간단하게 만든 화면은 제목 옆에 회색 배지 "간이 화면"을 단다.
   - 왼쪽 메뉴의 활성 항목·하위 메뉴와 `<title>` 도 화면에 맞게 바뀐다.
4. **입력과 검증**: 폼·모달은 실제로 입력을 받는다. 저장 버튼은 늘 눌리고, 빠진 필수 항목은 저장을 누를 때 항목 아래 오류 문구로 보여 준다(`patterns.md` 입력 오류 상태).
   저장되면 모달을 닫거나 화면을 옮기고 토스트로 결과를 알린다. 지우기처럼 되돌릴 수 없는 동작은 확인 모달을 거친다.
5. **실제 흐름을 따른다**: 무엇을 누르면 어디로 가고 무엇이 바뀌는지는 위키·코드로 확인한 실제 동작을 따른다
   (예: 새 보고서는 공시기준·언어를 골라 만들고 '원고작성중'으로 시작한다는 식). 확인하지 못한 동작은 지어서 넣되 4절 동작 표에 "가정"으로 적는다.
   - 등급(관리자·결재자·작성자 등)에 따라 버튼이 달라지는 화면이면 시안 도구 띠에 **역할 전환**을 두고 그에 맞게 버튼을 보이거나 감춘다.
6. **상태 보기 전환**: 빈 상태·오류·로딩처럼 데이터만으로 보기 어려운 상태는 시안 도구 띠에서 바꿔 볼 수 있게 한다.
   시안 도구 띠는 화면 왼쪽 아래(왼쪽 메뉴 오른쪽)에 `fixed z-toast rounded-component bg-background-secondary-inverse` 작은 띠로 두고, 실제 화면에는 없다는 걸 "시안 도구"라는 글자로 밝힌다.
7. **토스트**: 실제 앱은 `useTailwindToast` 를 쓰는데 테마 자료에 모양이 없다. 시안에서는
   `fixed bottom-8 left-1/2 -translate-x-1/2 z-toast rounded-component bg-background-secondary-inverse px-4 py-3 text-style-pre-body-06 text-text-primary-inverse` 로 3초 동안 보여 주고,
   개발로 넘길 때 "토스트 모양은 실제 컴포넌트로 확인 필요"라고 적는다.
8. **스크립트**: 파일 끝 `<script>` 하나에 둔다. 외부 라이브러리를 더 불러오지 않는다. 화면 조각은 템플릿 문자열로 그리되,
   3절 3의 클래스 규칙을 스크립트로 그리는 부분에도 똑같이 지킨다. 사용자가 입력한 글자를 화면에 넣을 때는 `&`·`<`·`>`·`"` 를 이스케이프한다.
   차트는 SVG 나 단순한 막대로 대신한다.

## 3-2. 직접 눌러 보고 확인하기
- 브라우저 도구가 있으면 시안을 열어 **4절 동작 표의 항목을 모두 한 번씩 눌러** 본다:
  화면 이동과 뒤로 가기, 만들기 → 목록·건수 반영, 필수 항목 오류, 지우기 확인, 역할·상태 전환, 데이터 초기화. 콘솔 오류가 없어야 한다.
- 안 되는 것이 있으면 고친 뒤 다시 누른다. 브라우저 도구가 없으면 "눌러 보는 확인은 하지 못함"이라고 알린다.

## 4. 결과 알리기
- 만든 파일 경로와, 브라우저에서 여는 방법(파일을 더블클릭)을 알린다. 인터넷이 연결돼 있어야 글꼴과 스타일이 적용된다고 덧붙인다.
- 아래를 짧게 정리한다.
  - **화면 구성**: 어떤 영역에 무엇을 놓았는지
  - **동작 표**: `| 누르는 곳 | 일어나는 일 | 근거 / 가정 |` 표로 눌러 볼 수 있는 것을 모두 적는다. 시안 범위 밖이라 토스트만 띄우는 곳도 적는다
  - **눌러 본 결과**: 3-2 에서 확인한 것과 확인하지 못한 것
  - **확인한 것 / 가정한 것**: 위키·코드로 확인한 내용(근거 포함)과 지어낸 부분
  - **개발로 넘길 때**: 각 부분이 실제로는 어떤 공용 컴포넌트에 해당하는지(예: 표 → `TanstackTableRenderer`, 폼 행 → `FormRowTable`, 버튼 → `Button variant="solidBlackRound"`)
  - 테마 기준: `SOURCE.md` 의 커밋
- 끝에 "시안입니다 - 실제 화면·운영 코드가 아니며, 사람이 확인하기 전에는 결정이 아닙니다"를 붙인다.
- 고칠 곳을 물어보고, 요청이 오면 같은 파일을 고친다.

## 하지 않는 것
- 운영 저장소에 넣을 React 코드를 만들지 않는다. 그 일은 개발자가 프론트 저장소 안에서 한다.
- 받은 테마 자료를 따로 파일로 저장해 두거나 다른 곳에 옮기지 않는다(시안 파일에 들어가는 뼈대는 예외).
- 위키 파일을 만들거나 고치지 않는다.
- 비밀번호·키·토큰·고객사 실데이터를 시안에 넣지 않는다.
